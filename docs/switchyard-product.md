# Switchyard: make the keyboard fit the person

Switchyard helps people describe work, improve the workflow, design physical
controls, connect supported tools, and try and refine the result. Direct editing
and proposals from an existing assistant edit the same configuration. Neither an
account nor an LLM is required for basic configuration.

Alex authorized this product direction in Revision 2 of the October 29, 2026 full-suite handover. The full integrated suite is required; the F77 is its pilot device, not its scope limit. A single-action demonstration is an intermediate test only.
The reusable product extends the earlier B122 control-plane scope. The canonical
22-control/65-assignment B122 protocol remains a versioned specialist preset;
its 27 acceptance gates remain open. They do not gate independent F77 or host
configuration features.

Linux leads implementation; Windows is required and macOS remains a future
target. The existing F77 is the first hardware test bed. B122 commissioning
waits for its arrival. No additional hardware is required.

The first useful loop is describe → proposal → keyboard preview → review →
private baseline → deliberate application → readback → trial → keep or restore.
Discovery must distinguish presence, identity, observation, control, and actual
task completion. A focused application does not prove a resumed task.

Portable profiles carry geometry, ordinary typing assumptions, workflows and
assignments. Local bindings, credentials, recordings, and work content stay on
the host. A Work label is not an isolation boundary. Managed use requires local
policy enforcement and separate protected stores before sensitive data use.

No firmware flash, bootloader operation, solenoid adjustment, public release,
license selection, upstream merge, or work-laptop deployment is authorized by
this build. Preserve existing Dvorak firmware, US host layout, native ChatGPT
voice repair, click protection, and unrelated work.
