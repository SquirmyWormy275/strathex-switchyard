# Choose the right client surface

**Your tools → Open the right app** distinguishes GitHub Copilot, Microsoft 365
Copilot, Claude desktop, Cursor Cloud Agents and Figma. Each choice shows its
exact destination, prerequisites, current workspace availability and source
reference. Browsing the catalog contacts no provider and starts no application.

On Linux, the Claude Desktop facts now distinguish this computer's vendor platform
baseline from the portable recipe. One bounded local `os-release` read and the
processor architecture identify supported versions, unsupported hosts, untested
Debian derivatives or unavailable metadata. Omarchy is reported as unsupported by
the vendor's desktop beta. This grants no permission and selects no alternate app.
The verified executable binding and Linux launch/focus path remain unfinished.
[Vendor requirements](https://code.claude.com/docs/en/desktop-linux),
[source and host evidence](evidence/linux-desktop-host-support-summary.json).
Six original integration groups pass 70 checks and one existing skip; the final
metadata group passes 19 overlapping checks. Installed adoption remains pending.

On Windows, select **Claude desktop → Set up Claude Desktop** to move directly
to its exact native-app setup. An already saved identity changes the link to
**Go to Claude Desktop controls**. Navigation reads saved metadata only; it does
not inspect or focus a window. Review a normal launch from those controls, or
separately review returning to an existing window. Work policy
and keyboard-only mode cannot enable these controls, and Linux offers no substitute.
Five original groups pass 59 interaction/integration checks with no skips,
including delayed-response refusal after a workspace change.
[Source evidence](evidence/client-native-navigation-source-summary.json).
The normal Linux installation contains this source and passes 62 served/API plus
107 metadata checks, preserving all 54 workspaces. This verifies Linux refusal
and saved metadata, not an actual Windows desktop.
[Installed evidence](evidence/installed-client-navigation-summary.json).

Choose **Review app launch** to inspect the fixed destination and workspace.
**Request this app launch** is a separate action. Its receipt distinguishes an
OS-accepted request from a verified application window, account or exact task.
Changing the selected client or workspace discards a pending review. Uncertain
outcomes stay in **Recent launch requests** and are never retried automatically.

A **Download recipe** action exports only the documented declarative target.
The file carries no credential, account, session or execution approval. Work
policy keeps export disabled and exposes only Microsoft 365. Personal exposes
its distinct supported clients; Microsoft 365 stays in Work, matching the
existing provider policy. Claude Desktop uses the separate saved-executable launch
review in its native controls; this homepage launch button stays disabled and no
web replacement is selected.

For exact saved coding-task connections, use the separate
[editor controls](editor-task-controls.md). The client homepage controls do not
resume a repository session or submit a prompt.

recovery. [Native app walkthrough](native-app-controls.md).
