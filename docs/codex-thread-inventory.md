# Read-only local Codex thread inventory

Use `npm run codex:threads` from the repository root on the owner's Omarchy workstation. On another host, pass an exact absolute Codex executable path after `--codex`. The command starts a short-lived local Codex App Server process, initializes the protocol, calls only `thread/list` for up to 25 recent CLI, VS Code, or App Server threads, and exits. It does not start or resume a thread, read prompts or turn items, send a model request, or dispatch a Switchyard chord.

The output contains exact thread IDs and **runtime state as seen by that short-lived App Server process**. `not-observed` means the saved thread was not loaded in this observer; it does not mean the task finished or that another Codex app is idle. `idle`, `active`, `waiting-on-approval`, and `error` are likewise local runtime observations, not companion-verified Switchyard task outcomes. Thread titles and previews are discarded. The first host probe returned 25 recent threads, all `not-observed`; no live session or provider capability has been promoted from this inventory.

Official [Codex App Server documentation](https://learn.chatgpt.com/docs/app-server) specifies `thread/list`, `thread/read`, runtime `status`, and the initialization handshake. It also documents `thread/status/changed` for a connected client. A future live adapter must keep an exact Switchyard-managed App Server connection and bind its thread ID, task ID, repository, target, and observation capability before reporting blocked or finished. A separate native ChatGPT desktop window remains unknown without its own supported observation path.
