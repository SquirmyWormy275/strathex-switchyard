# Model F Labs standard configurations

Switchyard starts with **Keep my place**: four task controls and a small workflow
for returning, checking progress, reviewing work and leaving a handoff. Open Home,
choose the keyboard, and select **Use this setup**. Customize stays one step away.
No assistant account is needed to browse, edit or export a reference layout.

The offline catalog contains **19 manufacturer-listed model/case/round combinations**, **104
named reference configurations**, three development geometry references and five
proposals without verified final geometry. A source reference does not establish
that a unit is currently available to buy. Inventory is not tracked here.

## What the standard setup contains

- **Return to my task:** a stable place for the exact connected conversation.
- **Check progress:** inspect a target's reported state and provenance.
- **Review the work:** bring work/context to an explicitly connected review target.
- **Leave a handoff:** prepare the next step and reviewed context.

The four controls use Super + Ctrl on number-row positions 1–4 when available,
then keypad 1–4, then F1–F4. The F50 alpha map uses R/S/V/H positions. Modifiers
for a separate pad can be held on the primary keyboard. These are **planned
assignments** until a supported target is connected and the host shortcut is
reviewed, applied and tried. Capability depends on the specific integration; a
preset does not implement or prove an agent operation. In particular, the current
suite role bridge primarily controls configuration conversations, not arbitrary
coding sessions. Physical role shortcut wiring is unfinished.

Physical choices come from the exact reference definition: ANSI / ISO / tie Enter,
regular / split / HHKB Shift, Backspace, Space, keypad and navigation choices as
available on each build. The F77 includes the named right-block and Num Lock
variants present in upstream release source. The split F15 and original split
ortholinear preview both halves, including their separate matrix identities and
rotated thumb clusters. Split previews namespace the second half's planning
matrix; those synthetic coordinates are never device write addresses.

**Reference typing** preserves upstream layer zero. **Dvorak in firmware · US host
layout** generates an independent Dvorak reference with the same physical action
positions. Choosing either changes only the plan, never firmware or host layout.
An existing user keymap, including the F77 pilot's Dvorak configuration, must be
read or imported separately before host connection. The compiler refuses a
`source-reference` profile. Colors, case finishes, printed languages, novelty caps
and serial numbers are not separate matrix configurations. A printed language
set does not establish its host layout or current keymap.

## Evidence and compatibility

Model/case/round names follow the [manufacturer catalog](https://modelfkeyboards.com/).
Controller and firmware guidance comes from the [manufacturer manual](https://modelfkeyboards.com/manual/).
Source is pinned to ploxiln/vial-qmk `c832c9b0edfa554c6e8344cb732f14620e63b210`
and mymakercorner/vial-qmk `761cb1c1b71ed91c48185f3e03465702b21e49f4`.
Every copied file and checksum is recorded in
[the source manifest](../third_party/model-f-catalog/SOURCES.json); GPL texts,
file notices and contributor credit are preserved in
[the local notice](../third_party/model-f-catalog/NOTICE.md) and
[attribution register](../ATTRIBUTION.md).

No firmware binary is shipped or flashed. Controller is deliberately `unknown`
in exported reference profiles. Classic/compact and controller build identity
must be reconciled against a real device read. The F50 NOS entry describes its
physical form using the modern F50 reference, and explicitly does not assert the
original IBM or replacement controller's matrix compatibility. Legacy nonshrunk
F104 and developmental alternate-controller definitions remain in the catalog's
source/build register for inspection, not automatic selection. All-pads diagnostic
maps are retained in source, excluded from normal setup choices.

The manufacturer's [new-design request page](https://modelfkeyboards.com/product/ultra-compact-new-model-f-designs-split-ortho-planck-preonic-6x12-f20-kinesis-advantage-unsaver-etc/)
distinguishes possible future designs from made boards. Development references
exist for 4×12, 5×12 and F20; these do not establish shipped hardware. No final
geometry is invented for 6×12, Kinesis-style designs, Unsaver or the proposed
Leyden Jar split ortholinear. They remain visible with a precise missing-source
status instead of a misleading downloadable hardware configuration.

## Build and export

Use the repository's pinned Node version:

```sh
mise exec node@24.14.0 -- npm run catalog:check
mise exec node@24.14.0 -- npm run catalog:export
mise exec node@24.14.0 -- npm run layout:studio
```

The export builds **126 portable JSON profiles**: the 104 named references plus
a Dvorak recommended reference for each of the 22 models with geometry.
`artifacts/model-f-standard-configurations/manifest.json` lists checksums,
provenance and the five unbuilt proposals. Existing output is never overwritten;
use `npm run catalog:export -- --dir /absolute/empty/directory` for a fresh bundle.
These JSON files can be imported through Customize → Open layout. No private
account, USB serial, task session, credential or machine path is included.
The generated JSON/catalog remains subject to the upstream terms in its notice.

`catalog:build` regenerates the bundled data from checksum-verified local sources,
without a network request or C execution. `catalog:check` detects drift. To update
sources, deliberately pin a new upstream commit, review source/license changes,
update the manifest and regenerate. Never treat a new upstream map as evidence
that an installed keyboard was updated.

## Validation

`tools/layout-studio/catalog.test.mjs` exercises all 104 named configurations,
portable round trips, four distinct modified controls, source-reference connection
rejection, physical choice alternatives, ISO outline shapes, rotated split halves,
choice bit packing and model/variant mismatch rejection. Geometry tests do not
prove ergonomics, printed legends or physical hardware behavior. Actual browser
and hardware acceptance are recorded in [current status](switchyard-status.md).
