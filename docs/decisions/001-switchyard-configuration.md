# 001 — Extend Studio with a narrow local configuration bridge

Accepted October 29, 2026. Direction: [product brief](../switchyard-product.md).

Retain the dependency-free JavaScript Studio and existing Node 24.14.0 runtime.
Keep shared protocol, companions and release tooling in their current locations;
avoid a mass move. `tools/layout-studio/` is the first product workspace.
`examples/alex-f77/` and `examples/alex-b122/` are sanitized entry points for the
personal showcase. Existing firmware and legends remain reference material.

Integrate the four Studio commits onto the Omarchy foundation in an isolated
worktree. They diverge at main; preserve the foundation's recorder, exact Codex
bindings, packaging fixes and native Linux test lane. Reconcile additive test
and documentation entries rather than replacing either branch.

Keep portable plans and structured proposals separate from local execution
connections. Version portable profiles and migrate the existing Studio v1 plans
without inventing device evidence. Reject unsupported versions without replacing
the open document. No imported text is executable or grants authority.

The initial effect is an explicitly reviewed Hyprland shortcut to focus the
already-running, verified native ChatGPT main window. Its closed adapter checks
the installed repaired executable and exact window, never a website, pet or
foreground typing. This is app focus, not exact task resume. Later agent actions
use the existing mediation contracts for their own authority requirements.

The browser bridge binds loopback, checks exact Host/Origin and fetch metadata,
requires an unpredictable per-launch bearer token, bounds input, disallows CORS,
and enforces expiring one-use reviews plus current-state preconditions. Only a
closed action map is accepted. Private transaction records stay outside Git.
Protect owner-controlled files and symlink boundaries. Same-user compromise
remains outside this authorization boundary.

Every effect saves a dated baseline and reason first, verifies compositor
readback, and exposes restore. Restore removes only the owned change while
preserving unrelated later edits; conflicts stop restoration. Durable records
survive process restarts. Firmware writes remain unavailable in this slice.

Read-only discovery never opens unrelated security keys or HID devices. F77
presence is a candidate identification until firmware and configuration
interfaces are read and verified. A saved Vial snapshot is historical evidence,
not a live device or recoverable firmware image.
